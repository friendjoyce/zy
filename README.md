# ZY：本地文档 RAG 问答

面向 AI 应用开发实习展示的本地 RAG 原型。读取 Markdown/TXT 文档，进行检索、证据拼接和 Ollama 生成，支持点击引用核对原文。

项目使用 AI 辅助开发；提交记录不代表使用者已独立掌握全部代码。当前交付范围是可运行、可复现、可演示的本地项目，不是生产服务。

## 三步运行

1. 准备 Python 3.10+，在仓库根目录打开终端。Python 代码仅使用标准库。
2. 无模型体验：运行 `python run.py`，打开 http://127.0.0.1:8080 。
3. 需要生成时，安装并启动 Ollama，执行 `ollama pull qwen3:4b`，然后运行 `python run.py --model qwen3:4b`。

模型下载需要网络和磁盘空间；运行需要足够的内存/显存。安装与模型准备由用户控制，启动器不会自动下载。`run.py` 先检查知识库和指定模型，再启动服务；Ctrl+C 停止。端口占用时会报错，不会结束其它进程。若环境变量已设置 OLLAMA_MODEL，即使没有 --model 也启用该模型；纯检索时清除该变量并保持网页生成选项未勾选。

## 演示

网页选择“多文档演示（虚构资料）”，算法选 BM25，分块选“标题随正文”，提问：

- Orion 当前文档上传上限是多少？旧规则是否仍然适用？
- Vega 文档保留期限是多少天？记录是否一致？
- Orion 文档系统最多支持多少并发用户？

点击回答中的 [1] 查看检索上下文和原文件段落。演示资料的产品与数值均为虚构。生成会受模型采样影响；有引用不代表答案正确。

自己的资料放入 `docs/`，选择“基础知识”知识库即可检索。支持 UTF-8 Markdown/TXT，暂不支持 PDF、网页抓取或文件上传。已有示例评估标签依赖文档内容，修改资料后要重新核对标签。

## 已实现

- Jaccard、TF-IDF、BM25 检索；网页问答支持后两种，默认 TF-IDF。
- 可选标题匹配重排、标题随正文分块；默认不启用实验策略。
- 进程内段落缓存，文件名与原段落编号追踪。
- 本地模型生成、无匹配短路、引用编号检查和点击原文。
- Recall/MRR/Hit@1、开发/测试划分、题集校验、真实实验记录。
- 启动自检、统一检查入口、Linux/Windows GitHub Actions。

## 验证与复现

```powershell
python check.py
python doctor.py --generate --model qwen3:4b
python evaluate_qa.py --validate-only
python acceptance.py --model qwen3:4b --output ../my-acceptance.json
```

`check.py` 运行自动测试、知识库读取检查和题集校验，不下载模型、不执行真实生成。`acceptance.py` 启动临时本机 HTTP 服务并实际调用模型，逐题记录回答；通过仅代表链路和预期模式正常，语义正确性仍需审核。

[云端检查](https://github.com/friendjoyce/zy/actions/workflows/checks.yml)在 main 推送及 PR 时运行。没有设置分支保护，检查失败不自动撤销提交。

## 实验结论与边界

BM25 对照中，多文档测试集只有三道可回答题，首条命中从 TF-IDF 的 2/3 到 3/3；其它套题指标持平。标题上下文分块使现有测试的纯标题返回条目从 3 条到 0 条。这些是已公开 AI 合成题上的小样本回归，不能写成业务准确率提升或泛化证明。

中文仍按单字匹配，没有语义 embedding、向量数据库或训练模型。缓存不是持久化索引；当前设计适合小资料。引用检查不判断语义支持，模型仍可能幻觉；提示词不是完整注入防护。服务器仅绑定本机，未实现认证、生产并发或公网部署，不应直接暴露公网。
